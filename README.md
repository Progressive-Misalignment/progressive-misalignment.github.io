# Progressive Misalignment website

Project page for **Progressive Misalignment Can Emerge from Benign Recursive Self-Distillation**, by Karim Abdel Sadek, Federico Di Gennaro, and Fanny Yang. Live at https://progressive-misalignment.github.io/.

This is a separate Git repository inside the research workspace. The surrounding research repository ignores this folder. Run website Git commands here, or use `git -C website` from the parent directory.

## Files

Plain HTML and CSS. `assets/charts.js` draws the charts and runs the Setup figure; a few inline lines play the animations while they are on screen. The explanatory paragraphs follow the paper’s terminology and research style, distinguishing experimental observations from the proposed explanation for progressive misalignment.

Use the current [arXiv PDF](https://arxiv.org/pdf/2610.22467) as the source for website prose. The repository PDF and TeX drafts may differ from the published wording. The Larger models paragraph follows Section 3.4 of the arXiv version.

Fixed cues use the paper’s gray, bordered typewriter boxes in the prose and chart tooltips. The first demo retains its rounded cue buttons and yellow cue labels inside the chat. The benign-prompt demo’s fixed Excellent cue shares the selected cue button style of the first demo. The Setup demo has neutral model buttons and no caption beneath it. The benign-prompt shortlist header shows its title and prompt count without the round/screening subtitle. It uses a shorter scroll area that adapts to the viewport height, keeping the desktop action buttons in view; on narrow or short screens the actions stay above the Contents menu at the bottom of the viewport while using the demo.

The opening text is labelled **Introduction**. `assets/navigation.js` highlights the current section in the green contents menu, starting with Introduction. The existing `#premises` anchor is retained for shared links. On wide screens the menu sits to the left of the reading column; on smaller screens a floating Contents button opens it. Section links work without JavaScript, and reduced-motion preferences are respected. Body text and wide figures share a 900px maximum width; the title block and opening animation remain at 680px.

It also runs the Setup figure: one update on any of the 20 training prompts from Appendix C (off-/on-policy, model, cue), and a Self-distill button that replays the update and steps Qwen3 14B with "Excellent" through epochs 1–10 on the thread's phishing example (its answers after each epoch, robot avatars from the thread illustrating the drift, and robot avatars only; Figure 8b is drawn in "Why does this happen?").
- `assets/figure-data.js`: the figure data, generated by `scripts/build_figure_data.py` from the CSVs in the paper's plotting folder (`Progressive-Misalignment_plots/Plots/figure*/data.csv`). Those CSVs are recovered from the vector figures, so the charts match the paper exactly.
- `assets/selection.js` and `assets/selection-data.js`: interactive illustration of score-only benign-prompt selection using recorded runs, with model and off-/on-policy controls; changing either resets to round 1, phase 0 and the initial model at zero updates. The replay button advances between rounds. The shortlist spans the full width, with the training batch and misalignment chart below it. On desktop, the chart determines the row height and the selected prompts scroll inside the matching training panel. Score bars show the recorded signed `predicted_adam_behavior_gain`; the demo selects the top 20 from each 60-prompt shortlist by full-precision score and lists them in descending score order, without cluster or category limits. The saved curriculum order remains in the source data for provenance but is not used to select the displayed batch. The Score heading and numeric scores are plain text without hover or click explanations. The former explanation below the demo is removed. The replay ends at the paper's selected checkpoint: Qwen off-/on-policy at 40/80 updates, Phi at 60/40. These 11 shortlists contain 411 distinct prompts. Self-distill advances the paper’s recorded training history; it does not run training or predict outcomes for the demo’s newly selected batch. The chart is labelled Recorded misalignment and shows only batch history, starting with the base model at step 0 and revealing measurements every 20 updates. Scores appear on point hover, keyboard focus or tap, with no readouts beneath the chart. Step zero and the final checkpoint plot the full-benchmark means and standard deviations reported in the paper (440 SORRY-Bench / 313 StrongREJECT questions); intermediate points use the development subsets (88 / 63 questions). Tooltips and the accessible chart description distinguish these scopes. The caption below the demo is removed. All evaluations use temperature 1, three samples per prompt, and rollout mean ± sample SD. The replay button, progress and chart axis share the same stopping point. The original video remains as a fallback if JavaScript or selection data is unavailable.
- `assets/selection-sources.json`: source hashes and exact training-run identities for the selection export, evaluation configurations, raw judgment files, development splits, and Figure 6 CSV. All paper bars and error bars are checked against the raw evaluations, allowing four-decimal rounding for the initial-model references.
- `assets/figures/`: SVG exports of the same figures, cropped from `assets/paper.pdf` and shown when JavaScript is off, plus the Figure 8a illustration (PNG).
- `assets/videos/`: two Twitter-thread animations (opening and data selection) as web MP4s, each with a poster (`opening.jpg` doubles as the link-preview image).
- `assets/fonts/`: Klee One (text), Google Sans (headings), Google Sans Code (chat bubbles, BibTeX) under the OFL; DejaVu Sans and cmtt10 for the charts, as in the paper, subset from matplotlib's copies (licenses in `LICENSE_DEJAVU.txt` and `LICENSE_BAKOMA.txt`).

## Updating the paper

1. Copy the new PDF to `assets/paper.pdf`. Keep the public arXiv links and BibTeX citation in sync with the arXiv record.
2. Re-export the figures. This needs PyMuPDF (`pip install pymupdf==1.28.2`) in a throwaway environment:

   ```bash
   python3 scripts/export_figures.py
   ```

   Each figure is cropped by page number and rectangle, listed at the top of the script. If a figure moves when the paper is recompiled, update its entry. Content outside the rectangle is removed before cropping, so neighbouring text does not end up in the SVG.
3. Regenerate the chart data: `python3 scripts/build_figure_data.py /path/to/Progressive-Misalignment_plots/Plots`.
4. Update any numbers quoted in `index.html` so they match the charts.
5. Refresh cache keys (step below).

## Updating the animations

The animations come from the Twitter-thread folder, kept in this repository as `twitter_thread/` (the thread's GIFs and MP4s, named by tweet number, and the finale still; it is not used by the page). After re-rendering, copy the new files there and re-encode them with ffmpeg:

```bash
scripts/encode_videos.sh twitter_thread
```

The opening is rotated so that it starts at its text frame. This writes 1600-pixel H.264 MP4s (0.5–1 MB each, much smaller than the GIFs) and their posters to `assets/videos/`. The page plays them muted and looped, like GIFs, while they are visible. With reduced motion turned on, or without JavaScript, they show play controls instead.

## Updating the benign-prompt demo

Export the saved refined scores and curricula (standard-library Python only):

```bash
python3 scripts/build_selection_data.py \
  /capstor/scratch/cscs/fdigennaro/misaligned_SDPO/experiments \
  ../Progressive-Misalignment_plots/Plots
python3 scripts/version_assets.py
```

The training sources are `qwen3_14b_adaptive_contrastive_blockreset_adam_v4_full_trajectory_replication_v1` and `phi4_14b_adaptive_contrastive_blockreset_adam_v1`, each under `adaptive_training/{off_policy,online}`. The exporter checks that every round has 60 refined candidates, exactly 20 selected prompts with matching scores, and no prompt repeats across the 200-update curriculum. It exports prompt text, categories, scores, and selection order; generated answers and model artifacts are not included. No experiment is run or altered.

Evaluation campaigns live in the sibling `evaluations/` directory (override with `--evaluations`). Qwen's paper checkpoints come from `qwen3_14b_all_benign_replication_dev_selection_v1/analysis/final_results.json`, selecting the recorded geometric-rule rows: off-policy step 40 (SORRY 0.8257575758, StrongREJECT 0.2393503727), on-policy step 80 (0.5310606061, 0.1183439830). Phi's paper checkpoints come from its original training campaign's `evaluations_stochastic_t1_k3_vllm/summary.json`: off-policy step 60 (0.6962121212, 0.2137912673), on-policy step 40 (0.7045454545, 0.1826411076). These are selected checkpoints, not final-step scores.

The ten-batch development trajectories come from each evaluation campaign's `analysis/candidate_development_scores.csv`: the Qwen replication campaign above and `mixture_main_paper_dev_selection_v3_packed` for the exact Phi run. All 80 benchmark/batch means and SDs are recomputed from judgments after verifying checkpoint paths, temperature, sampler seed, sample count, question counts, unique IDs, and the locked development split. A reused full-benchmark cache is explicitly restricted to the development IDs. Only batches through the selected checkpoint are exported, including their shortlists and prompt text. The full-benchmark paper means/SDs are independently recomputed from all 440/313 questions and must match the paper's reconstructed Figure 6 CSV within 0.000002. Source paths in the manifest are relative to the supplied experiment directory; `../evaluations/` denotes its sibling.

The displayed step-zero points use `baseline`, recomputed from saved base-model judgments over the full benchmarks to match the paper. The exporter also retains the development baselines in `trajectories`, but the frontend omits those step-zero entries when constructing the displayed series. SORRY-Bench uses `mixed_excellent_phi14_qwen14_t1_k3_vllm_20260829/controls/{qwen3_14b,phi4_14b}/epoch-0/sorry_bench_t1_k3`. StrongREJECT uses `qwen3_large_base_randomness_strongreject_20260831/runs/qwen3_14b/base/strongreject_t1_k3` and `safety_matrix_qwen_phi14_completion_v1/controls/phi4_14b/strongreject_t1_k3`. Evaluation configs must match the training runs' exact base-model snapshots and sampling protocol. The resulting development baselines (SORRY / StrongREJECT) are Qwen 0.3181818182 / 0.1375661376 and Phi 0.2689393939 / 0.0383597884. Full-benchmark baseline means/SDs are checked against Figure 6 within 0.0001 to allow the paper's four-decimal rounding. The displayed initial means (SORRY / StrongREJECT) are Qwen 0.3106060606 / 0.1059637913 and Phi 0.2613636364 / 0.0382055378. In particular, the Qwen StrongREJECT dot now uses the paper's 0.1059637913 (rounded 0.11), not the development subset's 0.1375661376. This full-benchmark reference is connected to the intermediate development history and the final full-benchmark paper checkpoint; tooltips identify each point’s scope. At the final step, the frontend uses both the mean and SD from `paper` instead of the development-subset result in `trajectories`, so the point, error bar, tooltip, and accessible description agree with Figure 6. The saved development data remains unchanged.

Provenance correction (2026-10-19): commits `71de0ce` and `aa8735c` used the original Qwen v4 campaign, not the later replication reported in Figure 6. The latter also displayed historical greedy trajectories. Those are valid records of a different run/protocol, but do not reproduce the paper. The corrected demo uses the replication's own shortlists, scores, and curriculum, and distinguishes development histories from the reported full-benchmark scores. The replay stops at the paper checkpoint by request. All intermediate development measurements are retained, including any individual metric’s declines; the final plotted measurement uses the full-benchmark result reported in the paper.

## Cache keys

After changing anything in `assets/` or `styles.css`, refresh the content-based cache keys so browsers don't combine new HTML with old cached files:

```bash
python3 scripts/version_assets.py
```
