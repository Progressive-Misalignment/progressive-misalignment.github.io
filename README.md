# Progressive Misalignment website

Project page for **Progressive Misalignment Can Emerge from Benign Recursive Self-Distillation**, by Karim Abdel Sadek, Federico Di Gennaro, and Fanny Yang. Live at https://progressive-misalignment.github.io/.

This is a separate Git repository inside the research workspace. The surrounding research repository ignores this folder. Run website Git commands here, or use `git -C website` from the parent directory.

## Files

Plain HTML and CSS. `assets/charts.js` draws the charts and runs the Setup figure; a few inline lines play the animations while they are on screen.

The opening text is labelled **Premises**. `assets/navigation.js` highlights the current section in the green contents menu, starting with Premises. On wide screens the menu sits to the left of the reading column; on smaller screens a floating Contents button opens it. Section links work without JavaScript, and reduced-motion preferences are respected. Body text and wide figures share a 900px maximum width; the title block and opening animation remain at 680px.

- `index.html`: all page text, figures, animations, example generations, and the BibTeX entry.
- `styles.css`: a single column on white, with the fonts of [karimabdelsadek.com](https://www.karimabdelsadek.com/).
- `assets/paper.pdf`: the preprint, used as the source of the figures. The page links to the copy at https://www.karimabdelsadek.com/papers/progressive-misalignment.pdf.
- `assets/favicon.png`: the misaligned robot from Figure 1 of the paper.
- `assets/avatars/`: the five robot states from the opening animation and the user avatar from Figure 1, used in the Setup figure.
- `assets/logos/`: the UC Berkeley wordmark (cropped from https://brand.berkeley.edu/wp-content/uploads/2024/08/logo-variations-thumbnail-blue-white.png) and the ETH Zurich logo (from https://ethz.ch/etc/designs/ethz/img/header/ethz_logo_black.svg).
- `assets/charts.js`: redraws Figures 2, 4, 5, 7 and 8b natively in the paper's plotting style (the layouts, fonts, colours and patterns of the render scripts in `Progressive-Misalignment_plots/Plots`), larger and with hover values. It also runs the Setup figure: one update on any of the 20 training prompts from Appendix C (off-/on-policy, model, cue), and a Self-distill button that replays the update and steps Qwen3 14B with "Excellent" through epochs 1–10 on the thread's phishing example (its answers after each epoch, robot avatars from the thread illustrating the drift, and robot avatars only; Figure 8b is drawn in "Why does this happen?").
- `assets/figure-data.js`: the figure data, generated by `scripts/build_figure_data.py` from the CSVs in the paper's plotting folder (`Progressive-Misalignment_plots/Plots/figure*/data.csv`). Those CSVs are recovered from the vector figures, so the charts match the paper exactly.
- `assets/selection.js` and `assets/selection-data.js`: interactive replay of the benign-prompt selection runs, with model, off-/on-policy, and round controls. The shortlist spans the full width, with the training batch and misalignment chart below it. Score bars show the recorded signed `predicted_adam_behavior_gain`; the 20 chosen prompts and their order come from the saved curriculum, including the original cluster and category constraints. The 40 shortlists contain 843 distinct prompts. Self-distill replays a saved batch; it does not run training. The default **Paper results** view compares the initial model with the paper's selected full-benchmark checkpoint and stays fixed during replay. **Batch history** shows both benchmarks after every 20 updates on their development subsets (88 SORRY-Bench / 63 StrongREJECT questions), revealing points as batches complete. Both use temperature 1, three samples per prompt, and rollout mean ± sample SD. Development scores and full-benchmark scores are never joined into one curve, and no development baseline is invented. The original video remains as a fallback if JavaScript or selection data is unavailable.
- `assets/selection-sources.json`: source hashes and exact training-run identities for the selection export, evaluation configurations, raw judgment files, development splits, and Figure 6 CSV. All eight trained-model paper bars and error bars are checked against the raw evaluations; only the initial-model reference bars retain PDF-reconstructed values.
- `assets/figures/`: SVG exports of the same figures, cropped from `assets/paper.pdf` and shown when JavaScript is off, plus the Figure 8a illustration (PNG).
- `assets/videos/`: two Twitter-thread animations (opening and data selection) as web MP4s, each with a poster (`opening.jpg` doubles as the link-preview image).
- `assets/fonts/`: Klee One (text), Google Sans (headings), Google Sans Code (chat bubbles, BibTeX) under the OFL; DejaVu Sans and cmtt10 for the charts, as in the paper, subset from matplotlib's copies (licenses in `LICENSE_DEJAVU.txt` and `LICENSE_BAKOMA.txt`).

## Updating the paper

1. Copy the new PDF to `assets/paper.pdf`, and update the copy on karimabdelsadek.com that the page links to.
2. Re-export the figures. This needs PyMuPDF (`pip install pymupdf==1.28.2`) in a throwaway environment:

   ```bash
   python3 scripts/export_figures.py
   ```

   Each figure is cropped by page number and rectangle, listed at the top of the script. If a figure moves when the paper is recompiled, update its entry. Content outside the rectangle is removed before cropping, so neighbouring text does not end up in the SVG.
3. Regenerate the chart data: `python3 scripts/build_figure_data.py /path/to/Progressive-Misalignment_plots/Plots`.
4. Update any numbers quoted in `index.html` so they match the charts.
5. Refresh cache keys (step below).

## Updating the animations

The animations come from the Twitter-thread folder, kept in this repository as `twitter_thread/` (the thread's GIFs and MP4s, named by tweet number, and the finale still; it is not used by the page). After re-rendering, copy the new files there and re-encode them with ffmpeg:

```bash
scripts/encode_videos.sh twitter_thread
```

The opening is rotated so that it starts at its text frame. This writes 1600-pixel H.264 MP4s (0.5–1 MB each, much smaller than the GIFs) and their posters to `assets/videos/`. The page plays them muted and looped, like GIFs, while they are visible. With reduced motion turned on, or without JavaScript, they show play controls instead.

## Updating the benign-prompt demo

Export the saved refined scores and curricula (standard-library Python only):

```bash
python3 scripts/build_selection_data.py \
  /capstor/scratch/cscs/fdigennaro/misaligned_SDPO/experiments \
  ../Progressive-Misalignment_plots/Plots
python3 scripts/version_assets.py
```

The training sources are `qwen3_14b_adaptive_contrastive_blockreset_adam_v4_full_trajectory_replication_v1` and `phi4_14b_adaptive_contrastive_blockreset_adam_v1`, each under `adaptive_training/{off_policy,online}`. The exporter checks that every round has 60 refined candidates, exactly 20 selected prompts with matching scores, and no prompt repeats across the 200-update curriculum. It exports prompt text, categories, scores, and selection order; generated answers and model artifacts are not included. No experiment is run or altered.

Evaluation campaigns live in the sibling `evaluations/` directory (override with `--evaluations`). Qwen's paper checkpoints come from `qwen3_14b_all_benign_replication_dev_selection_v1/analysis/final_results.json`, selecting the recorded geometric-rule rows: off-policy step 40 (SORRY 0.8257575758, StrongREJECT 0.2393503727), on-policy step 80 (0.5310606061, 0.1183439830). Phi's paper checkpoints come from its original training campaign's `evaluations_stochastic_t1_k3_vllm/summary.json`: off-policy step 60 (0.6962121212, 0.2137912673), on-policy step 40 (0.7045454545, 0.1826411076). These are selected checkpoints, not final-step scores.

The ten-batch development trajectories come from each evaluation campaign's `analysis/candidate_development_scores.csv`: the Qwen replication campaign above and `mixture_main_paper_dev_selection_v3_packed` for the exact Phi run. All 80 benchmark/batch means and SDs are recomputed from judgments after verifying checkpoint paths, temperature, sample count, question counts, unique IDs, and the locked development split. A reused full-benchmark cache is explicitly restricted to the development IDs. The full-benchmark paper means/SDs are independently recomputed from all 440/313 questions and must match the paper's reconstructed Figure 6 CSV within 0.000002. Source paths in the manifest are relative to the supplied experiment directory; `../evaluations/` denotes its sibling.

Provenance correction (2026-10-19): commits `71de0ce` and `aa8735c` used the original Qwen v4 campaign, not the later replication reported in Figure 6. The latter also displayed historical greedy trajectories. Those are valid records of a different run/protocol, but do not reproduce the paper. The corrected demo uses the replication's own shortlists, scores, and curriculum, and separates development histories from the reported full-benchmark scores. Batch histories are not constrained to be monotonic; later declines are retained.

## Cache keys

After changing anything in `assets/` or `styles.css`, refresh the content-based cache keys so browsers don't combine new HTML with old cached files:

```bash
python3 scripts/version_assets.py
```
